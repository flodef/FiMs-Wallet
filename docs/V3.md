# FiMs Wallet V3 — Refonte complète

## État des lieux (V2 actuelle)

**Frontend** : Next.js (app router, quasi tout en `'use client'`), mélange antd + Tremor + composants custom + swiper, navigation par contexte sans routing, toutes les deps en `"latest"`.

**Backend** : 3 sources de données hétérogènes —

- Vercel Postgres : `users`, `transactions` (`app/api/database/*`)
- Firebase/Firestore (`app/api/firebase/*`)
- Google Sheets : dashboard, historic, tokens, portfolio, userHistoric, transactions, prix (`utils/processData.ts` + `api/spreadsheet`)
- API Solana read-only : `getAssets`, `getPrices` (Jupiter lite), `getTransactions`

**Modèle** : pas un wallet — connexion par simple username, aucune clé, aucun signing. `@solana/pay` présent (QR codes).

## Décision

- **Base** : fork de [samui-wallet](https://github.com/samui-build/samui-wallet) (MIT, Turbo + Bun monorepo)
- **Custody** : vrai wallet — clés gérées in-app (vault samui), import clé Solflare, signature de tx
- **Données** : Neon = source de vérité unique ; migration de Postgres + Firebase + Google Sheets

## Pourquoi samui-wallet

| Apport samui                                                                                                        | Besoin FiMs V3                                     |
| ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| `keypair`, `vault`, `wallet-standard`                                                                               | import clé Solflare, signing in-app                |
| `solana-client` (@solana/kit)                                                                                       | remplace web3.js legacy                            |
| `feature-portfolio`, `feature-onboarding`, `feature-settings`, `feature-shell`, `feature-explorer`, `feature-tools` | squelette des écrans                               |
| UI Radix/base-ui + Tailwind (style shadcn)                                                                          | stack UI unique, fin du mélange antd/tremor/custom |
| `i18n`, `flags`, Dexie local-first                                                                                  | prefs locales, feature flags                       |

**Limites identifiées** :

- Pas de DB serveur (Dexie = IndexedDB local) → tout le modèle communautaire FiMs (users, dons, tontine) reste à construire sur Neon
- `apps/web` = Vite + Cloudflare, pas Next.js → changement de plateforme de déploiement (à valider : rester sur Vercel possible pour un build statique Vite ; `apps/api` = worker Cloudflare)
- Projet jeune (oct. 2025), roadmap en cours — suivre upstream ou assumer le fork
- `apps/extension` et `apps/site` probablement superflus pour FiMs → élaguer

## Décisions d'architecture (tranchées)

- **Repo** : [flodef/FiMs-Wallet-V3](https://github.com/flodef/FiMs-Wallet-V3) — nouveau repo initialisé depuis samui (pas de fork GitHub — samui inactif depuis ~4 mois), remote `upstream → samui-build/samui-wallet` pour cherry-pick/merge sélectif si upstream repart
- **Déploiement** : Cloudflare (Pages + Workers) — cible native samui, free tier généreux, Vercel Free saturé
- **Backend** : API Neon dans `apps/api` (worker Cloudflare), tout au même endroit

## Schéma Neon cible (à affiner)

- `users` (pseudo, adresse Solana, privacy, sns, created_at)
- `transactions` (user_id, date, type[deposit|withdrawal|donation|payment|tontine|conversion|cex_in|cex_out], movement, cost, signature, token)
- `donations` (user_id, org|tontine, amount, date) — séparation dons asso/tontine
- `tokens` / `token_meta` (symbol, mint, description, inception_price, volatility, duration, yearly_yield)
- `historic` / `user_historic` (snapshots quotidiens pour graphs)
- `prices` (cache historique prix — remplace l'onglet Sheet)
- `address_book` (user_id, label, address, type[nexo|coinbase|binance|fimseur])
- `votes`, `vote_options` (outil de vote)
- Migration : script ETL Sheets + Firestore + Vercel PG → Neon, avec validation
